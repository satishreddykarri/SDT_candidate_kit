# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health / L73` | Handled `/health` by returning `{"status": "ok"}` hardcoded without actually checking MongoDB. | The endpoint returns 200 even if the database cluster is completely offline. | Added a `try/except` block enclosing a simple `client.admin.command('ping')` and returning a `503` if it fails. |
| 2 | `create_employee / L79` | Relied on application-side `check-then-insert` (`find_one`) for unique `emp_code`. | Executing massive bursts of simultaneous `POST /employees` payloads for the same dummy code will eventually interlace and commit duplicates. | Added idempotent MongoDB unique index generation via FastAPI `@asynccontextmanager` lifespan. Removed `find_one` and caught `DuplicateKeyError`. |
| 3 | `EmployeeIn / L58` | No Pydantic rule enforcing `shift_start` must differ from `shift_end`. | Sending an `EmployeeIn` body with matching hours will yield a `201` from the starter file instead of a `422`. | Appended a `@model_validator` that strictly ensures `shift_start != shift_end`. |
| 4 | `create_employee (Response) / L83` | Converted naive datetimes and leaked them naturally as ISO strings via FastAPI default serialization. | Open-ended inspection verifies endpoint returns `2026-X-XDT....` but openapi schema strictly demands Epoch milliseconds as integers. | Stored `truncate_to_seconds(datetime.now(timezone.utc))` internally but mutated the dictionary by parsing timestamps as integer milliseconds prior to `return`. |
| 5 | `list_employees / L93` | Skip cursor pagination math logic was `page * page_size`, which erroneously skips page 1 bounds entirely rather than skipping `0` documents. | Firing `GET /employees?page=1` will unexpectedly drop the first 20 records in the response offset. | Redefined variable `skip = (page - 1) * page_size`. |
| 6 | `list_employees / L93` | The `total` count always evaluates the aggregate database size (`db.employees.count_documents({})`) dropping query filters. | Filtering by a `department` returns the valid partial subset array in `items`, but the `total` scalar field erroneously represents all departments. | Replaced the empty dict match with `total = db.employees.count_documents(q)`. |
| 7 | `punch_in / L102` | Used `datetime.fromtimestamp(x/1000)` locally (naive) which fails to represent guaranteed UTC offsets or cleanly truncate to seconds (R1). | If a punch-in happens off-timezone, datetimes become massively disparate logic errors. Unrounded microseconds break comparisons. | Initialized timestamps explicitly to `timezone.utc` and stripped microseconds via `.replace(microsecond=0)`. |
| 8 | `punch_in / L103` | Crude `.date()` IST evaluation failed the rule for overnight shifts, creating broken daily boundaries. | A shift spanning `22:00` to `06:00` with an employee punching in at `01:00 UTC` fails to belong to the "previous day" shift. | Wrote `get_attendance_date` helper combining manual timezone conversion (`.astimezone(IST)`) and logical checking if strictly less than overnight boundaries. |
| 9 | `punch_in / L104` | Missed MongoDB uniqueness rules. It checked if an `emp` exists manually but suffers race condition vulnerabilities for duplicates. | Rapid duplicate punch-in inserts for the exact same employee and calendar date creates distinct documents inside MongoDB rather than throwing `409` conflict. | Added compound multi-key index `[("emp_code", 1), ("date", 1)]` as unique in lifespan config. Replaced checking logic with `DuplicateKeyError` mapping. |
| 10 | `punch_in / L101` | Lacked `None` boundary check for employee existence querying. Raises `500 Server Error` exception on dict subscripting. | Invoking `punch-in` for an unknown `emp_code` yielded a stack trace `TypeError: 'NoneType' object is not subscriptable` resulting in 500 status rather than 404. | Inserted `if not emp: raise HTTPException(404, "Unknown employee")` manually. |
| 11 | `list_attendance L125` / `punch_in L113` | Artificially injects `"id"` scalar strings into response mapping from PyMongo internal `_id` `ObjectId` classes. | JSON response dumps include `"id": "..."` strictly forbidden by Openapi `AttendanceRecord` schemas that address via `emp_code`/`date`. | Snipped out assignments logic pushing `str(res.inserted_id)` entirely. |
| 12 | `list_attendance / L144` | Pulled down the entire Mongo collection entirely into python local script memory as a raw `list(...)` explicitly prior to sorting logic. | If database encompasses the defined >`~100k+` payloads, the service halts out-of-memory or locks resources heavily processing manual internal logic. | Refactored collection fetch to rely on `.skip(n).limit(n)` explicitly and `.sort([("date", -1), ("emp_code", 1)])` directly using a cursor. |
| 13 | `compute_late_minutes / L35` | Used `.replace` on the exact naive local incoming timestamp string resulting in overnight failure bounds. | Fails completely against overnight boundaries breaking R2 bounds logic. | Created robust IST datetimes parsing specifically targeting decoupled components `h` and `m`. |
| 14 | `compute_work_hours / L41` | Native Python banker's `round()` half-even rounding violated the precise "2 decimals half-up" R8 standard mandate natively explicitly required. | Time logs resolving to bounds exactly on `4.495` output unpredictably instead of accurately rolling upwards to `.50`. | Replaced the entire module with Python's formal `decimal` package invoking `ROUND_HALF_UP`. |
| 15 | `compute_overtime / L46` | Used `date_str` to build end interval checking. For overnight setups falling over the day gap interval, this compares completely mismatched interval offsets. | `01:00` clock outs on midnight-overnight shifts calculated backwards interval limits. | Injected explicit shift bounds check. `if shift_end <= shift_start:` strictly advances timezone definitions by `+ timedelta(days=1)`. |


### Behaviors Reviewed but Considered Not Defects

1.  **FastAPI Request Query Formats:** Examined how Python relies on default inputs parsing limits but deemed non-defect. I implemented custom `Query(ge=1)` clamps strictly, but technically standard string typing endpoints were operable.
2.  **Using Naive PyMongo Insertions:** Passing standard timezone aware datetime elements explicitly triggers BSON date conversions naturally in Python. The starter's lack of serialization manually parsing UTC -> BSON string mapping isn't a defect since the PyMongo driver handles this out of the box correctly.
3.  **Returning Full Sets Over Arrays:** Fastapi handles dumping lists out natively if annotated properly. The base endpoints didn't include formal annotations but didn't actually crash; they only violated specification formatting lightly which was repaired seamlessly during broader updates.
